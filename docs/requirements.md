# qwen-demo 需求设计文档

相关架构设计见：[architecture.md](./architecture.md)

## 1. 项目定位

`qwen-demo` 是一个用于面试展示、同时可作为 GitHub 项目的 Qwen 全栈 Demo。

它不是只演示一次模型调用，而是展示一个相对完整的 AI 应用形态：

- 前后端分离
- 多轮会话
- 联网搜索增强
- 图片和文档输入
- 后续可扩展到项目级上下文与知识库

从产品视角看，它是一个本地部署的多模态 AI 工作台；从系统视角看，它会逐步从“请求级会话编排”演进到“带轻量 Agent 编排的 AI 应用”。

## 2. 项目目标

### 2.1 核心目标

- 做出一个可以本地运行的 Qwen Demo
- 展示从单轮问答到长会话管理的演进过程
- 展示搜索增强和多模态输入能力
- 形成一个结构清晰、可持续扩展的 GitHub 项目

### 2.2 展示目标

该项目主要服务于两类场景：

- 面试展示：体现 AI 应用设计能力、全栈落地能力、功能拆解能力
- GitHub 展示：体现项目结构、需求抽象、工程演进过程

## 3. 用户与核心场景

### 3.1 目标用户

- 面试官
- GitHub 访问者
- 项目作者本人

### 3.2 核心场景

1. 基础问答  
   用户输入一个文本问题，系统返回回答。

2. 连续追问  
   用户围绕同一主题多轮提问，系统保持上下文一致。

3. 搜索增强  
   用户开启联网搜索后提问，系统结合搜索结果回答，并展示来源链接。

4. 多模态理解  
   用户上传图片或文档作为当前消息附件，系统结合附件内容进行总结、问答或信息提取。

5. 项目化工作  
   用户在某个项目下创建多个会话，并在后续扩展中为该项目挂接知识库或长期记忆。

## 4. 产品范围

### 4.1 产品形态

- 本地部署
- 前后端分离
- 左侧：项目列表、会话列表
- 右侧：聊天区、输入区、附件区

### 4.2 会话能力

- 支持单轮文本问答
- 支持多轮连续对话
- 支持会话历史展示
- 支持长会话的上下文压缩

### 4.3 搜索能力

- 支持用户主动开启联网搜索
- 支持系统结合搜索结果生成回答
- 支持在回答后展示来源链接

### 4.4 多模态能力

图片能力：

- 图片上传
- 图片问答
- OCR
- 图表理解
- 表格理解

文档能力：

- 文档上传
- 文档总结
- 文档问答
- 关键信息提取

当前计划支持的文档格式：

- `md`
- `pdf`
- `docx`

### 4.5 项目能力

- 支持项目维度组织会话
- 一个项目下支持多个会话
- 后续支持项目级知识库
- 后续支持长期记忆

## 5. 输入与数据组织

### 5.1 输入类型

- 文本
- 图片
- 文档

### 5.2 附件规则

- 图片和文档默认作为当前消息附件使用
- 系统需要记录附件与消息的关联关系
- 附件本身负责文件原件和元数据管理
- 文档解析、图片理解分别由对应能力模块处理
- 后续可按需要保存为项目级资源

### 5.3 请求处理方式

系统当前需要支持两类处理方式：

- 会话编排：负责 `SendMessage` 这种请求级主流程
- 轻量 Agent 编排：在搜索、文档、图片等场景下负责多步能力调度

第一阶段只做轻量版，不追求复杂 Planner、多 Agent 协作或长链路自主执行。

## 6. 分阶段规划

### 第一阶段：基础框架 + 文本问答最小闭环

目标：完成最小可运行闭环。

包含内容：

- 前后端基础框架
- 基础聊天界面
- 单轮文本问答
- 多轮会话基础能力

### 第二阶段：会话管理 + 上下文压缩

目标：让系统具备稳定的连续对话能力。

包含内容：

- 会话历史
- 基础上下文管理
- 长会话压缩

### 第三阶段：联网搜索 + 来源链接

目标：让系统具备外部信息增强能力。

包含内容：

- 搜索开关
- 联网搜索
- 搜索结果融合回答
- 来源链接展示

### 第四阶段：图片 / 文档上传、理解、问答

目标：让系统具备多模态输入能力。

包含内容：

- 图片上传与理解
- 文档上传与理解
- 总结、问答、信息提取

### 第五阶段：RAG / 项目级上下文

目标：让系统从“会话型 Demo”演进到“项目型 AI 工作台”。

包含内容：

- 项目级知识库
- RAG
- 项目长期记忆

## 7. 第一版范围

第一版以“能稳定演示”为目标，优先保证主线闭环，不追求一次做全。

第一版建议至少覆盖：

- 基础框架
- 单轮问答
- 多轮对话
- 会话历史
- 上下文压缩
- 联网搜索开关
- 来源链接展示

## 8. 暂不包含

- 用户系统
- 在线部署
- 多用户隔离
- 复杂权限设计
- 复杂 Planner
- 多 Agent 协作

## 9. 成功标准

当项目达到以下状态时，可认为 Demo 已具备较强展示价值：

- 能稳定完成文本问答
- 能支撑多轮连续对话
- 能在长会话中进行基本上下文管理
- 能按需联网搜索并展示来源链接
- 能逐步接入图片与文档理解
- 项目结构清晰，便于继续扩展
