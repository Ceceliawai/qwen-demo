# qwen-demo 需求设计文档

## 1. 项目背景

`qwen-demo` 是一个用于面试展示、同时可作为 GitHub 项目的 Qwen 全栈 Demo。

项目目标不是只演示一次模型调用，而是展示一个相对完整的 AI 应用形态，包括：

- 前后端分离的项目结构
- 面向任务的多轮对话体验
- 联网搜索增强
- 图片和文档输入
- 后续可扩展到项目级上下文与知识库

## 2. 项目目标

### 2.1 核心目标

- 做出一个可以本地运行的 Qwen Demo
- 展示从单轮问答到长会话管理的演进过程
- 展示搜索增强和多模态输入能力
- 形成一个结构清晰、可持续扩展的 GitHub 项目

### 2.2 展示目标

该项目主要服务于两类场景：

- 面试展示：体现 AI 应用设计能力、全栈落地能力、功能拆解能力
- GitHub 展示：体现项目结构、需求抽象、产品思路和工程演进过程

## 3. 产品定位

这是一个本地部署、前后端分离的多模态 AI 工作台，而不是单纯的聊天页面。

它的核心价值在于：用户可以围绕一个任务持续对话，系统能够记住上下文；用户可以按需开启联网搜索；后续还能结合图片和文档继续提问，并逐步扩展到项目级知识和长期记忆。

## 4. 用户与使用场景

### 4.1 目标用户

- 面试官
- GitHub 访问者
- 项目作者本人

### 4.2 典型场景

#### 场景一：基础问答

用户输入一个文本问题，系统返回回答。

#### 场景二：连续追问

用户围绕同一主题进行多轮提问，系统能够保持上下文一致。

#### 场景三：搜索增强

用户开启联网搜索后提问，系统结合搜索结果回答，并在界面中展示来源链接。

#### 场景四：多模态理解

用户上传图片或文档作为当前消息附件，系统结合附件内容进行总结、问答或信息提取。

#### 场景五：项目化工作

用户在某个项目下创建多个会话，并在后续扩展中为该项目挂接知识库或长期记忆。

## 5. 产品形态

### 5.1 部署方式

- 本地部署
- 前后端分离

### 5.2 界面结构

- 左侧：项目列表、会话列表
- 右侧：聊天区、输入区、附件区

### 5.3 搜索交互

- 前端提供“是否联网搜索”的开关
- 搜索结果在回答后展示可点击链接
- 第一版不强制展示标题和摘要

## 6. 功能需求

### 6.1 会话能力

- 支持单轮文本问答
- 支持多轮连续对话
- 支持会话历史展示
- 支持长会话的上下文压缩

### 6.2 搜索能力

- 支持用户主动开启联网搜索
- 支持模型结合搜索结果生成回答
- 支持在回答后展示来源链接

### 6.3 多模态能力

#### 图片能力

- 图片上传
- 图片问答
- OCR
- 图表理解
- 表格理解

#### 文档能力

- 文档上传
- 文档总结
- 文档问答
- 关键信息提取

当前计划支持的文档格式：

- `md`
- `pdf`
- `docx`

### 6.4 项目能力

- 支持项目维度组织会话
- 一个项目下支持多个会话
- 后续支持项目级知识库
- 后续支持长期记忆

## 7. 输入与数据组织

### 7.1 输入类型

- 文本
- 图片
- 文档

### 7.2 附件规则

- 图片和文档默认作为当前消息附件使用
- 后续可按需要保存为项目级资源

## 8. 分阶段规划

### 第一阶段：基础框架 + 单轮文本问答

目标：完成最小可运行闭环。

包含内容：

- 前后端基础框架
- 基础聊天界面
- 单轮文本问答

### 第二阶段：多轮对话 + 会话历史 + 上下文压缩

目标：让系统具备连续对话能力。

包含内容：

- 多轮对话
- 会话历史
- 基础上下文管理
- 长会话压缩

### 第三阶段：联网搜索 + 来源链接

目标：让系统具备外部信息增强能力。

包含内容：

- 搜索开关
- 联网搜索
- 搜索结果融合回答
- 来源链接展示

### 第四阶段：图片 / 文档上传、理解、问答

目标：让系统具备多模态输入能力。

包含内容：

- 图片上传与理解
- 文档上传与理解
- 总结、问答、信息提取

### 第五阶段：RAG / 项目级上下文

目标：让系统从“会话型 demo”演进到“项目型 AI 工作台”。

包含内容：

- 项目级知识库
- RAG
- 项目长期记忆

## 9. 第一版范围

第一版以“能稳定演示”为目标，优先保证主线闭环，不追求一次做全。

第一版建议至少覆盖：

- 基础框架
- 单轮问答
- 多轮对话
- 会话历史
- 上下文压缩
- 联网搜索开关
- 来源链接展示

## 10. 暂不包含

- 用户系统
- 在线部署
- 多用户隔离
- 复杂权限设计

## 11. 后续扩展方向

- 更完整的多模态处理
- 扫描版文档处理优化
- 项目级知识库与长期记忆
- 更好的上下文治理策略
- 更完整的演示 UI

## 12. 成功标准

当项目达到以下状态时，可认为 Demo 已具备较强展示价值：

- 能稳定完成文本问答
- 能支撑多轮连续对话
- 能在长会话中进行基本上下文管理
- 能按需联网搜索并展示来源链接
- 能逐步接入图片与文档理解
- 项目结构清晰，便于继续扩展
